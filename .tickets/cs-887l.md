# Unconditional ClearThinking post in show_agent_stream_end may trigger redundant UI repaint

**File**: claude_storm/display.py
**Line(s)**: 649
**Description**: The previous implementation guarded ClearThinking behind `if not self._thinking_cleared` to avoid a redundant stop/repaint of the ThinkingBar when it had already been cleared. The new implementation unconditionally posts ClearThinking(0) on every stream end, even after a normal stream where UpdateThinkingLabel was already sent. While ThinkingBar.stop() is cheap, the unconditional path means the bar always receives a stop + refresh call regardless of its current state. In high-frequency or rapid-turn scenarios (e.g., many short agent turns), this is a minor but unnecessary extra refresh cycle per turn.
**Suggested Fix**: Track whether the bar is currently active before posting ClearThinking, or reuse `_stream_responding` to gate the call. Alternatively, make ThinkingBar.stop() a no-op when already inactive (guard with `if not self._active: return`) so the extra call is harmless with zero UI cost.
